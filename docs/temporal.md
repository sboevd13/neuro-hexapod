# Последовательное обучение поведения: Temporal Double DQN

Экспериментальная ветка: `feature/temporal-q-learning`. Проверенная базовая V5,
PPO-контроллер и алгоритм исследования помещения остаются прежними. Новая модель
**опционально** оценивает три локальных действия: движение вперёд, поворот влево
и вправо. Планировщик по карте выбирает маршрут и сохраняет возможность
перехватить управление.

## Что обучается

Раз в 15 шагов управления (0,3 с) записываются наблюдение, фактически
выполненное действие, награда, новое наблюдение и признак завершения.
Награда использует изменение расстояния до точки маршрута, поворота к ней,
прирост исследованной площади и штрафы за столкновения/падение.

Double DQN обучается на переходах с дисконтированием `gamma=0.96`:

`Q(s,a) <- r + gamma * Q_target(s', argmax_safe Q_online(s', a'))`

У завершённых переходов член будущей ценности обнуляется; при выборе
будущего действия учитывается защитная маска впереди препятствий. Раз
в несколько эпох обновляется целевая сеть. Используются Huber loss, Adam,
клиппинг градиентов и replay из разных сцен. Это **последовательное** RL,
но пока офлайн, без обучения весов во время демонстрации.

## Запуск: запись и обучение

При наличии пакетов из `requirements-laptop.txt`:

```bash
python explore_laptop.py --reference --seed 7 --seconds 60 \
  --record-transitions --output runs/temporal/seed_7
python train_temporal.py \
  --transitions runs/temporal/seed_7/transitions.jsonl \
  --init-model models/behavior_v1.json --epochs 45 \
  --output runs/temporal/q_model.json
python explore_laptop.py --reference --seed 11 --seconds 90 \
  --temporal-model runs/temporal/q_model.json --view
```

Во время сбора опыта с разведкой можно добавить
`--temporal-epsilon 0.2 --record-transitions`, а затем дообучать на
дополнительных `transitions.jsonl`. Ничего не изменяется в сохранённой
модели, пока явно не указан новый `--output`.

Сравнение двух алгоритмов на одинаковых seed:

```bash
python benchmark_autonomy.py --mode baseline --seeds 47 59 71 \
  --seconds 60 --output runs/temporal/eval
python benchmark_autonomy.py --mode temporal \
  --temporal-model runs/temporal/q_model.json \
  --seeds 47 59 71 --seconds 60 --output runs/temporal/eval
```

Результат зависит от обучающей выборки: улучшение покрытия карты **не
гарантируется**. Используйте независимые от обучающих seed и сравнивайте
покрытие, столкновения, падения, число вмешательств. Проверки CI собирают
больше тренировочных и тестовых сценариев; контрольный запуск фиксируется
в GitHub Actions.

## Ограничения и безопасность

- Входы — девять лучей из идеализированного дальномера, направление и расстояние
  до точки маршрута. Робот **пока не видит камерой**; его поза точно известна
  только благодаря симулятору. Это не SLAM.
- Сеть управляет лишь локальными командами; она не заменяет управление
  18 суставами и не пересчитывает мировую карту.
- Движение вперёд блокируется при близком препятствии. В качестве
  дополнительной защиты нейросеть не может заменить поворот планировщика
  движением вперёд или противоположным поворотом. Изменение планировщика
  разрешается только для раннего обхода близкого препятствия.
  При опасных поворотах, повторных разворотах и столкновениях работает
  исходный планировщик/контур восстановления. Это не формальное доказательство
  безопасности реального робота.
- PPO для суставов не включён в автоматические проверки этого этапа: физика
  MuJoCo выполняет эталонную V5, чтобы отделить ошибки навигации от ходьбы.
- Все испытания в виртуальных комнатах. Перенос на физическое устройство
  требует датчиков, локализации, контроллера безопасности и отдельной проверки.

## Проверенные результаты (GitHub Actions, 19 ноября 2026)

Обученный экземпляр сохранён в `models/temporal_q_experimental.json`; его
можно запустить без повторного обучения:

```bash
python explore_laptop.py --reference --seconds 90 --seed 47 \
  --temporal-model models/temporal_q_experimental.json --view
```

Результаты **на шести отложенных комнатах**: baseline — 64,90% покрытия,
Double DQN — 64,65%. В обоих случаях 0 столкновений и 0 падений; нейросеть
приняла 76 локальных решений, однако лишь дважды изменила команду планировщика.

На **шести дополнительных новых комнатах** оба варианта дали одинаковые 66,94%
и 0 столкновений/падений, поскольку защитный арбитр не допустил ни одной
команды-замены от нейросети. Этот результат **не является улучшением**.
В четырёх тренировочных комнатах с epsilon-greedy произошли 3 контакта;
их нельзя скрывать при оценке безопасности системы.

Модель пока **экспериментальная**: учится дисконтированному будущему вознаграждению
на реальных переходах MuJoCo, но не продемонстрировала превосходство над
исходным алгоритмом. Для прогресса нужны более насыщенные данными наблюдения
препятствий и расширение действий, а затем отдельные безопасные испытания.
Полный численный отчёт — `validation/temporal_q_v1.json`.
