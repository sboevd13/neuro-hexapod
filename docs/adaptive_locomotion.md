# Адаптивное управление

## Интерфейсы

Один такт длится 20 мс. Функция `tick` читает команду и наблюдение, передаёт их контроллеру и отправляет результат приводам. Только адаптер MuJoCo загружает симулятор. Для инференса на ноутбуке достаточно NumPy.

| Интерфейс | Реализации | Что передаётся |
|---|---|---|
| `CommandSource` | Клавиатура, геймпад SDL, запись с метками времени | Нормированное движение вперёд, влево и вращение |
| `SensorSource` | MuJoCo и `LiveSensors` для кадров камеры и показаний IMU с метками времени | Время, ориентация и угловая скорость IMU, наблюдение переднего сектора со временем кадра |
| `GaitController` | Базовая V5 с поправками PPO, адаптивное управление | Целевые геометрические углы 18 суставов и режим |
| `Actuators` | Приводы MuJoCo и `CalibratedActuators` для отправки кадра в драйвер платы | Тройки углов с проверенными диапазонами и скоростью изменения |

Порядок ног в контроллере — FL, ML, BL, FR, MR, BR. Суставы в тройке — coxa, femur, tibia. Оси корпуса — X вперёд, Y влево, Z вверх. Используются метры, секунды и радианы. Сервы физического робота не измеряют угол. Поэтому контроллеру доступны предыдущие **заданные** углы. Истинное положение в мире и контакты используются для оценки испытаний и наладки модели.

Для воспроизводимого ввода подайте `--replay commands.json`. Например, запись `[{"at":0,"forward":1},{"at":4},{"at":5,"turn":0.5},{"at":7}]` даёт четыре секунды ходьбы, остановку и поворот.

## Камера и выбор шага

Метрический профиль использует модель откалиброванной камеры глубины. Лучи измеряют видимые поверхности в оптической проекции RGB-камеры. Закрытые корпусом пиксели получают статус отсутствующего измерения. По наклону IMU облако точек выравнивается относительно горизонта. Детектор оценивает просвет, боковые расстояния и высоту опорной поверхности в трёх секторах. Идентификаторы препятствий и название трассы не входят в наблюдение контроллера.

Монокулярная модель принимает кадр 80 × 48 и наклон корпуса. При обучении метрические наблюдения служат метками. Данные включают случайные ракурсы, полные проходы по трассам, изменения освещённости и положения робота. Классы — свободный путь, перекладина, коридор, неровности, преграда. В коридоре модель оценивает ширину, а при различимых границах пола и стен доля прохода слева уточняется по лучам откалиброванной RGB-камеры с поправкой на IMU. Это помогает держать корпус по центру после выхода из низкого тоннеля. Работу с реальной камерой предстоит проверить на кадрах с её объектива.

На открытой площадке работает направленная V5 с обученными ограниченными поправками PPO. При обнаружении препятствия контроллер плавно переходит к трёхопорной походке. Под перекладиной он опускает корпус и шире расставляет ноги. В коридоре поворачивает тазовые суставы и укорачивает шаг средних ног. На настиле увеличивает подъём и смещает точки опоры по измеренной высоте поверхности. Поза удерживается после выхода преграды из поля зрения, чтобы успели пройти задние ноги. Оценка препятствий действует в переднем секторе обзора. Движение назад остаётся доступно оператору для отступления.

## Соответствие прошивке

Сверка с материалами руководителя включала `hardware/cad/Hexapod.f3z`, STL верхней пластины (188 × 104 × 6,5 мм), `firmware/hexapod/src/core/IKSolver.cpp`, штатный порядок ног и индивидуальные поправки серв. Кинематические длины старой модели — 51,077 / 64,648 / 114,615 мм. Для дипломной модели используются значения прошивки — **51 / 65 / 121 мм** от оси до оси и до расчётной точки стопы. На собранном экземпляре фактическую точку контакта и зазор под нагрузкой потребуется измерить.

XML и обратная кинематика используют один набор размеров. Пределы каждого из 18 суставов пересечены с доступными 0–180° с учётом смещений и калибровок. `firmware_degrees` переводит выход в физические градусы и порядок прошивки FR, MR, BR, BL, ML, FL. Тесты сопоставляют этот выход с независимой формой уравнений оригинальной прошивки. Сценарий `scripts/check_firmware_ik.py` позволяет сравнить команды непосредственно с C++-решателем из исходного ZIP.

Для переноса контроллер продолжит работу на ноутбуке. Хостовые адаптеры `LiveSensors` и `CalibratedActuators` уже принимают кадры и IMU с метками времени и собирают атомарный кадр из 18 калиброванных целей для драйвера платы. Устаревшее измерение останавливает движение вперёд. До подключения железа их проверяет тест с записанными входами и приёмником исходящих байтов. Штатный протокол руководителя поддерживает команды джойстика и выбор походки. Режим приёма целого кадра углов, проверка нулей и испытания под нагрузкой относятся к этапу работы с оборудованием.

## Воспроизведение

```bash
python -m unittest discover -s tests -p test_diploma.py -v
python -m hexapod.benchmark --both --seeds 1307 1601 2141
python -m pip install -r requirements-diploma-training.txt
python -m hexapod.training --run-dir runs/diploma-ppo
python -m hexapod.train_vision --report runs/camera-training.json
```

На Linux без экрана выберите `MUJOCO_GL=egl` с Mesa EGL либо `MUJOCO_GL=osmesa` с пакетом `libosmesa6`. Для небольших CPU-моделей подходит `OPENBLAS_NUM_THREADS=1`. Для обычного запуска окна на ноутбуке с дисплеем эти настройки не требуются.

PPO обучается в физических эпизодах MuJoCo. Из контрольных точек экспортируется модель с лучшей оценкой среди прошедших проверку движения. На трассах обе системы получают одинаковые команды и начальные условия. Успех требует финиша, устойчивости, соблюдения боковой границы и отсутствия касаний стен или крыши с проверкой на каждом шаге физики 2 мс. На настиле контакт с опорными плитами является частью шага. На непроходимой трассе требуется остановка до стены без контакта. Для RGB отдельно оцениваются качество на кадрах и результат полного прохода.

## Результаты от 25 ноября 2026 года

Во всех заездах оператор задавал одинаковое движение вперёд. Номер варианта менял трение, начальное положение, геометрию и внешний вид препятствий. В таблице указано число успешных испытаний из восьми для каждой трассы и каждого режима. Базовая походка и адаптивный режим с глубиной проходили одни и те же варианты. Для RGB использован отдельный набор из восьми вариантов, включая четыре новых после исправления центрирования.

| Трасса | Адаптация, глубина + IMU | Адаптация, RGB + IMU | Походка без адаптации |
|---|---:|---:|---:|
| Ровная площадка | 8/8 | 8/8 | 8/8 |
| Тоннель, высота 14,3–15,3 см | 8/8 | 8/8 | 0/8 |
| Коридор, ширина 44,8–46 см | 8/8 | 8/8 | 0/8 |
| Настил с плитами высотой до 3,8 см | 8/8 | 8/8 | 8/8 |

| Тоннель, коридор и настил подряд | 8/8 | 8/8 | 0/8 |
| **Всего** | **48/48** | **48/48** | **16/48** |

На комбинированной трассе робот преодолел 3,4 м за 28,0–28,5 секунды модельного времени. На отдельной трассе с перекладиной минимальная высота центра корпуса составила 5,7–5,8 см. В дополнительных испытаниях с проёмами 10,5 см по высоте и 32 см по ширине оба режима остановили робота перед входом без касания.
